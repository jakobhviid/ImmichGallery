# Advanced search

Search is available in the sidebar and through the toolbar search field. Submit text with Return. Edit > Find opens Search and focuses the toolbar field with ⌘F; Search Filters… opens the filter sheet with ⌥⌘F.

The toolbar field is an `NSSearchField` in a plain customizable toolbar item (`SearchToolbar.swift`), not SwiftUI's `.searchable`: in the window's customizable toolbar the system search item made AppKit throw while laying out the toolbar. Every page ends its toolbar with it (`pageToolbar`), so it stays at the trailing edge. The window's `SearchFieldModel` holds the text; Return or the clear button submits it, and submitting empty text while on Search clears the results. In a window narrower than 980 points the field becomes a Search button until clicked, and returns to a button when left empty. The field offers no completion menu: recent searches are on the search start page and in the Recent Searches menu. The results view offers Context, File Name, Description, and Text in Images modes. Context is shown only when smart search is enabled; OCR requires the server's `ocr` feature flag. Empty text with active filters uses metadata search.

Filters combine people, country/state/city, camera make/model/lens, inclusive local calendar dates, photo/video type, archived assets, favorites, assets outside albums, and an exact one-to-five-star rating. Rating controls appear only when `users/me/preferences.ratings.enabled` is true. People are paged, show face thumbnails, and can be filtered by name among loaded people. Suggestion menus use the server's distinct metadata values; each menu shows all available values and the text field permits manual entry. Requests wait 250 ms after parent changes and send only the relevant location or camera parents. Changing a parent location or camera clears its dependent fields.

Chips above results reopen the editable filter sheet and have individual remove buttons. The people chip shows the selected names. Recent searches preserve the complete query, filters, and selected order, replacing an existing entry when only the order changes. They keep at most 20 entries, and can be cleared. They are stored in UserDefaults under a server API URL and user ID key, without tokens. Missing fields in older history entries decode to defaults. Restored modes are clamped to server capabilities. No history is persisted if the user ID is unavailable. The Recent Searches menu restores their complete filters. The search start page is aligned to the top and offers quick Favorites, Photos and Videos filters, six recent searches that restore their complete query, and up to twelve city tiles using representative photo previews. Locked representatives are omitted. Mode-specific guidance explains what can be searched. Results retain a compact, adaptive header with mode, filters, sort and history menus inside the inspector content host.

The Sort Results picker offers Default Order, Newest First, and Oldest First. Default preserves server relevance for smart search and newest-first metadata results. Metadata date order is requested on the server, including later pages. Upstream Immich smart search has no date-order parameter, so date sorting takes up to the first 500 matches in server relevance order, then sorts that subset using `fileCreatedAt` and asset ID to break ties. This also works with Noodle without changing the server API. Date-sorted smart requests ask for 500 results; if the server returns smaller pages, collection stops as soon as 500 unique matches have been gathered or pagination ends. Extra matches are discarded before date sorting and no further page is requested once the limit is reached. A visible notice explains the 500-result limit and the grid reports the loaded count. This is a relevance-rank limit, not a similarity threshold, so weak matches may remain and relevant matches beyond the limit are omitted. Switching date direction reuses the collected subset for the same query, while Refresh fetches it again. Repeated or invalid page tokens fail the search when another page is needed, and duplicate asset IDs are removed. A page failure fails the search rather than showing a partially collected set; switching to another query cancels the old search. Default relevance order and metadata searches retain their existing pagination. The selected order is saved in recent searches, defaults for older entries, and survives clearing filters.

Results reuse AssetGridContainer, including infinite paging, selection, context menus, the viewer, export, and inspector. Later-page failures now surface through the grid's existing error alert and stop automatic paging until an explicit Refresh with ⌘R. This also covers viewer navigation past the last loaded asset. Only one search grid is cached at a time. Empty pages no longer create an empty results section that hides the No Results state.

## Contracts checked

- Immich v3.3.5 `open-api/immich-openapi-specs.json`: POST `/search/smart`, POST `/search/metadata`, GET `/search/suggestions`, GET `/search/explore`, GET `/people`, GET `/server/features`, GET `/users/me/preferences`; SmartSearchDto, MetadataSearchDto, SearchSuggestionType, SearchExploreResponseDto, SearchExploreItem, RatingsResponse, and search paging fields.
- Official v3.3.5 web source: `web/src/lib/managers/search-manager.svelte.ts`, `SearchTextSection.svelte`, `SearchLocationSection.svelte`, `SearchDisplaySection.svelte`, and `search-bar-utils.ts`. OCR maps to metadata `ocr`, archive maps to `visibility: archive`, and date limits cover complete days.
- https://docs.immich.app/features/searching/ for supported modes and filters. https://api.immich.app was fetched, but its client-rendered endpoint pages were not readable through the documentation fetcher; the version-pinned OpenAPI and official web source supply the exact contract.
- Apple's SwiftUI reference for searchSuggestions, DatePicker, and sheet. These predate macOS 26. The other UI primitives follow the existing app's SwiftUI patterns.

## Compatibility

v3.3.5 marks flat search filters deprecated in favor of SearchFilter, but accepts them and uses them in its own web client. Using the flat form retains v2 compatibility. Smart search uses numbered pages; metadata accepts either numbered pages or the returned cursor. The session feature flags supply OCR availability without another server/features request on opening Search. A missing smart endpoint falls back to filename metadata search. Missing OCR flags hide OCR; missing ratings preferences hide ratings. Suggestion 404s hide the suggestion menu while allowing typed filters; unavailable explore data is omitted. A v2 server was not available for runtime checks.

Exact ratings 1–5 are supported. An explicit unrated filter and null metadata values are not exposed. Explore dates are omitted because the endpoint returns month buckets rather than Things categories. Only city explore groups are exposed.
